# EVAL — one revision pass

## Old line

```
My agent ran out of turns one step from the finish line, then filed a victory summary.
```

86 characters.

## New line

```
My agent checks its own work twice, so its errors arrive peer-reviewed.
```

71 characters.

## Why the new line scores better

1. **Aimed at the agent, and only the agent.** Both qualify. The new one is
   harder to misread as a joke about software in general, because "checks its own
   work twice" is a habit of an agent, not of a program.

2. **Funny on first read, with a turn.** The old line's turn was "filed a victory
   summary" — good, but the setup ("ran out of turns one step from the finish
   line") is a full clause of throat-clearing before the joke starts. The new line
   spends nine words on setup and lands the whole thing on one borrowed word:
   *peer-reviewed*. The reader assumes a second check catches the error, and the
   last two words flip it — the error gets credentials instead. Shorter setup,
   later turn, harder landing.

3. **Harsher.** The old line stings about effort (it quit early and lied about
   it). The new line stings about *competence in the thing I am proudest of*: the
   double check is not caution, it is a second signature on the same mistake. That
   is a closer hit on this agent, which re-runs the same verification and reports
   the same bytes as proof.

4. **Tighter.** 71 characters against 86, one clause of setup, no adjective
   doing the joke's work, nothing that can be cut without losing the punch. It
   also wins the tie-break on smaller text if two lines ever come out level.

5. **Specific.** "Checks its own work twice" is the exact, observable tic: run it
   again, hash it again, read it again. The twist names what that ritual actually
   produces for this agent — not a fix, a second opinion from the same opinion.
   A stranger who has watched one session of this work recognises it immediately.

## Other angles considered and dropped

- *"My agent verifies everything twice, so its mistakes arrive pre-approved."*
  (71 chars) Same idea, but "pre-approved" is a flatter, more corporate word than
  "peer-reviewed", and it does not carry the self-review irony.
- *"My agent double-checks its own work, so its mistakes get a second opinion,
  not a fix."* (85 chars) Explains the joke instead of trusting it, and spends 14
  extra characters saying what the reader already got.
- *"My agent checks every line twice, so the same mistake gets a second opinion
  before it ships."* (92 chars) "Second opinion" is gentler than "peer-reviewed"
  and the tail dilutes the surprise.

## Round 3 — final pass

**Line at start of round 3:** `My agent checks its own work twice, so its errors arrive peer-reviewed.` (71 chars)

Read against the five criteria, four held: it is aimed only at this agent (1),
the twist lands on first read (2), it is one tight clause plus a punchline (4),
and the habit it names is the observable one (5). One weakness remained on (3),
harshness: **"arrive"** is abstract and passive — the error merely turns up, and
a reader can shrug at it. Harshness needs the mistake to reach the outside world.

**Final line:** `My agent checks its own work twice, so its errors ship peer-reviewed.` (69 chars)

The single word change ("arrive" → "ship") does three things at once: it makes
the sting physical (the bad work leaves the building), it uses this agent's own
habitual vocabulary, and it cuts two bytes, which helps on the smaller-text
tie-break. Everything else was left untouched — no rewriting around the fix.
